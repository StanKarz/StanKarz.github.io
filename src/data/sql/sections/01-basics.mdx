- A **primary key** (PK) identifies a row. Postgres enforces it: a second row with `memid 1` fails with `duplicate key value violates unique constraint "members_pkey"`, and a NULL key fails too. Names have no such rule, which is why there are two Darren Smiths (1 and 37) and only `memid` tells them apart.
- A **foreign key** (FK) holds another row's primary key. `bookings` has two, so it links members to facilities: many members book many facilities, stored as a row per booking.
- `recommendedby` is a foreign key into its *own* table: it points at another member. That is a self-reference, not a circular dependency; nothing breaks. But to show a recommender's name you read `members` twice, once as the member and once as the recommender, and give the two copies different aliases (`mems`, `rec`) so SQL knows which `firstname` you mean. Hover Janice above to see it.

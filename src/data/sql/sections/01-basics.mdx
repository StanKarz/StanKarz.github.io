A table stores one kind of thing, and each row is one of them. A **primary key** identifies a row uniquely: `members.memid`, `facilities.facid`, `bookings.bookid`. A **foreign key** is a column whose values point at a primary key somewhere else: `bookings.memid` points at `members.memid`, and `bookings.facid` at `facilities.facid`.

- **One-to-many.** One member has many bookings; each booking has one member.
- **Many-to-many.** A member books many facilities and a facility is booked by many members. Nothing stores that directly: `bookings` sits in the middle as a *linking table*, holding a foreign key to each side.
- **A key that points at its own table.** `members.recommendedby` references `members.memid`. The same table plays two roles, the member and their recommender, so any query that resolves it needs two aliases for one table. It comes back in joins, subqueries and updates.

Keys exist because names collide. There are two Darren Smiths in this data (memid 1 and 37), and only `memid` tells them apart. Several later sections lean on that.

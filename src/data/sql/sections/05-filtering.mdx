| You write | It means |
|---|---|
| `'Tennis'` | A string literal |
| `"Tennis"` | An identifier: a column or table called Tennis |
| `name in ('Tennis Court 1', 'Tennis Court 2')` | Exact match against a list. Never searches inside a string. |
| `name like '%Tennis%'` | Pattern match. `%` is any run of characters (including none), `_` is exactly one. |
| `name ilike '%tennis%'` | Case-insensitive LIKE (Postgres) |
| `name ~ 'Court [12]$'` | Regex match (Postgres). `~*` for case-insensitive. |
| `strpos(name, 'Tennis') > 0` | Substring check without a pattern |

Use the tightest filter that fits. If you know the exact values, `=` or `IN` says so; `LIKE '%Tennis%'` casts a wider net, and here it also catches the table tennis table.

**AND binds tighter than OR.** `where a or b and c` means `a or (b and c)`. Parenthesise anything that mixes them.

```sql
-- facilities with "Tennis" in the name: 3 rows, one of them Table Tennis
select name from cd.facilities where name like '%Tennis%';

-- the two tennis courts and nothing else
select name from cd.facilities where name in ('Tennis Court 1', 'Tennis Court 2');
```

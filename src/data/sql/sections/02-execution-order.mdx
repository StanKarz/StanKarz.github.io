You write `SELECT` first; it runs fifth.

<ExecutionOrder client:visible />

- Anything that runs before SELECT can't see its aliases: WHERE, GROUP BY, HAVING. ORDER BY can.
- Aggregates filter in HAVING, not WHERE. Window functions can't be filtered in either: wrap the query and filter outside.
- This is the *logical* order. The planner reorders the physical work freely, so it says nothing about speed.

Further reading: Julia Evans, [SQL queries don't start with SELECT](https://jvns.ca/blog/2019/10/03/sql-queries-don-t-start-with-select/).

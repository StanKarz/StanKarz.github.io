NULL means unknown or missing. It is not 0 and it is not an empty string. Any comparison involving NULL, including `NULL = NULL`, is neither true nor false but **unknown**, and WHERE only keeps rows that are true. So you test for it with `IS NULL` and `IS NOT NULL`, never `= NULL`.

| `AND` | TRUE | FALSE | UNKNOWN |
|---|---|---|---|
| **TRUE** | TRUE | FALSE | UNKNOWN |
| **FALSE** | FALSE | FALSE | FALSE |
| **UNKNOWN** | UNKNOWN | FALSE | UNKNOWN |

| `OR` | TRUE | FALSE | UNKNOWN |
|---|---|---|---|
| **TRUE** | TRUE | TRUE | TRUE |
| **FALSE** | TRUE | FALSE | UNKNOWN |
| **UNKNOWN** | TRUE | UNKNOWN | UNKNOWN |

`NOT UNKNOWN` is still UNKNOWN. The one row of those tables that bites hardest is UNKNOWN inside an AND chain, which is exactly what NOT IN builds:

### Where NULLs come from, and what eats them

- **Outer joins create them** for unmatched rows.
- **Aggregates skip them.** `COUNT(*)` counts rows; `COUNT(col)` counts non-null values. `SUM` over no non-null values is NULL, not 0.
- **`COALESCE(a, b, …)`** returns its first non-null argument. The usual use is `coalesce(sum(slots), 0)`.
- **A scalar subquery that finds no row returns NULL.** That's why members with no recommender get a blank recommender column with no special handling.
- **`concat(a, ' ', b)`** treats NULL as an empty string. **`a || ' ' || b`** returns NULL if any piece is NULL.

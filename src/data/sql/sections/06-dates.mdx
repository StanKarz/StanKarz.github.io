A `timestamp` is a date plus a time. Compare it with a bare date and the date is read as midnight, so `starttime = '2012-09-21'` matches only bookings at exactly 00:00:00. In this data that's one booking out of six that day.

To match a whole day:

```sql
-- cast to a date: easiest to read
where starttime::date = '2012-09-21'

-- half-open range: leaves the column alone, so an index on starttime can be used
where starttime >= '2012-09-21' and starttime < '2012-09-22'
```

Prefer the half-open range to `BETWEEN`. BETWEEN includes both ends, so `between '2012-09-21' and '2012-09-22'` also catches a booking at midnight on the 22nd. There is one in this data.

`::` (two colons) is the Postgres cast. The standard spelling is `cast(starttime as date)`.

### Taking timestamps apart

| Expression | For `2012-09-21 17:30` | Notes |
|---|---|---|
| `extract(month from starttime)` | `9` | Standard SQL |
| `date_part('month', starttime)` | `9` | Postgres spelling of the same thing |
| `date_trunc('month', starttime)` | `2012-09-01 00:00:00` | Keeps the year, so September 2012 and September 2013 stay separate when you group |
| `starttime::date` | `2012-09-21` | Drops the time |

```sql
-- slots booked per month
select date_trunc('month', starttime) as month, sum(slots)
from cd.bookings
group by 1
order by 1;
```

ON decides which rows pair up. The join type only decides what happens to rows that find no partner.

<JoinExplorer client:visible />

Count rows after every join, the way you would after a pandas merge. Joining from the many side to the one side on its key should never change the row count. If it does, the key isn't what you think.

### Patterns

```sql
-- anti-join: members with no bookings
select mems.memid
from cd.members mems
left join cd.bookings bks on bks.memid = mems.memid
where bks.memid is null;

-- semi-join: members with a booking, each once
select mems.memid
from cd.members mems
where exists (select 1 from cd.bookings bks where bks.memid = mems.memid);

-- self join: each member with their recommender
select mems.firstname, rec.firstname as recommender
from cd.members mems
left join cd.members rec on rec.memid = mems.recommendedby;
```

`FROM a, b` is a cross join. RIGHT JOIN is LEFT JOIN with the tables swapped; prefer LEFT.

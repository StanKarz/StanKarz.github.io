### INSERT

```sql
insert into cd.facilities (facid, name, membercost, guestcost, initialoutlay, monthlymaintenance)
values (5, 'Spa', 20, 30, 100000, 800),
       (6, 'Squash Court 2', 3.5, 17.5, 5000, 80);

-- the next id from a subquery: one item in VALUES, in its own parentheses
insert into cd.facilities (facid, name, membercost, guestcost, initialoutlay, monthlymaintenance)
values ((select max(facid) + 1 from cd.facilities), 'Spa', 20, 30, 100000, 800);

-- or insert the result of a query
insert into cd.facilities (facid, name, membercost, guestcost, initialoutlay, monthlymaintenance)
select max(facid) + 1, 'Spa', 20, 30, 100000, 800 from cd.facilities;
```

`max(id) + 1` is fine for exercises, but two sessions can read the same max at the same time. Real tables use an identity or serial column and let the database hand out ids.

### UPDATE

```sql
update cd.facilities
set membercost = membercost * 1.1     -- 10% more is × 1.1
where name = 'Tennis Court 2';
```

There is no compound assignment (`*=`). Without WHERE, every row changes.

To set one row from another row's values, Postgres has `UPDATE … FROM`, with one alias for the row being written and one for the row being read:

```sql
update cd.facilities f2
set membercost = f1.membercost * 1.1,
    guestcost  = f1.guestcost * 1.1
from cd.facilities f1
where f1.name = 'Tennis Court 1'
  and f2.name = 'Tennis Court 2';
```

### DELETE

```sql
-- members who have never booked
delete from cd.members
where memid not in (select memid from cd.bookings);

-- the NULL-safe version
delete from cd.members m
where not exists (select 1 from cd.bookings b where b.memid = m.memid);
```

The first is safe here only because `bookings.memid` can't be NULL. See [the NOT IN trap](#null). Postgres also has `DELETE … USING` for join-style deletes.

### Habits

- Write the SELECT with the same WHERE first, look at the rows, then swap SELECT for UPDATE or DELETE.
- When experimenting, wrap it in a transaction: `begin; … ; rollback;` undoes everything.
